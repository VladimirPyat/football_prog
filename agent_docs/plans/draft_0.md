# План Этапа 0: База данных и конфигурация

## 1. Обзор
Цель данного этапа — заложить фундамент данных приложения. Необходимо спроектировать схему базы данных, настроить миграции с помощью Alembic, а также реализовать механизм загрузки первоначальных настроек конкурса (seed).

## 2. Ключевые решения
- **СУБД**: PostgreSQL (для production) и SQLite (для dev/тестов).
- **ORM**: SQLAlchemy 2.0+ с асинхронной поддержкой.
- **Типы данных**:
  - Все даты хранятся в формате `TIMESTAMPTZ` (UTC).
  - Счета матчей и прогнозов хранятся как `INTEGER`. Важно: отсутствие прогноза — это отсутствие записи или `NULL`, но ни в коем случае не `0`, так как `0` — это значащий счет.
- **Констрейнты (Constraints)**:
  - Ограничение на счета: `CHECK (score1 >= 0 AND score1 <= 20)` и `CHECK (score2 >= 0 AND score2 <= 20)`. Максимальное значение (20) берется из конфигурации, но на уровне БД фиксируется для надежности.
  - Уникальность прогноза: `UNIQUE(user_id, round_id, match_id)`.
  - Уникальность команд в матче: `CHECK (team1_id != team2_id)`.
- **Конфигурация конкурса**:
  - Настройки (лимиты, правила начисления очков) загружаются из `contest_defaults.json` и сохраняются в таблицу `contest_settings` при инициализации.
  - После активации конкурса поле `is_locked` переводится в `TRUE`, запрещая изменения.
