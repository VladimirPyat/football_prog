# Ручное тестирование организатора (SUPERVISOR) — сценарии

Чек-лист для роли **SUPERVISOR**: что проверить в админке, на каком маршруте и какое поведение ожидается. Использовать перед релизом или после крупных изменений фронта/бэка.

**Источники:** `docs/04_supervisor_scenario.md`, `docs/01_tech_regulations.md`, [contest_lifecycle_flow.md](../agent_docs/contracts/contest_lifecycle_flow.md), [frontend_api_integration.md](../agent_docs/contracts/frontend_api_integration.md), [STATUS_REFERENCE.md](STATUS_REFERENCE.md).

**Скриншоты (эталон):** `docs/screens/supervisor_*.jpg`

---

## Как пользоваться чек-листом


| Колонка       | Значение                                                                                                 |
| ------------- | -------------------------------------------------------------------------------------------------------- |
| **ID**        | Стабильный идентификатор сценария (связь с UC / этапами)                                                 |
| **Статус**    | Заполняет тестировщик: `✅` ок · `⚠️` частично · `❌` ошибка · `—` не проверял · `🔲` N/A (не реализовано) |
| **Авто**      | Автотесты: Vitest / pytest / Playwright (если есть)                                                      |
| **Замечания** | Известные пробелы; добавляйте дату/находки                                                               |


**Фазы конкурса:**

- **SETUP (настройка)** — `contest.status = DRAFT`, `is_locked = false`
- **RUNNING (идёт)** — после первой активации тура, `is_locked = true`
- **Fixture (dev)** — после `dev_setup.py` + `finalize_dev_fixture`: туры 1–9 `PUBLISHED`, 10 `CALCULATED`, 11 `CLOSED` ([DEV_SETUP.md](DEV_SETUP.md))

**Вход (dev):** организатор — пароль `SEED_SUPERVISOR_PASSWORD`, см. [BOOTSTRAP_USERS.md](BOOTSTRAP_USERS.md).

**Сброс фикстуры после прохода по «Турам» / «Результатам»:**

```bash
uv run python src/scripts/dev_setup.py --finalize-fixture-only
```

### 10.1 Очистка лишних конкурсов (dev / E2E)

E2E и ручные прогоны создают много черновиков и «E2E Setup …» в списке конкурсов. Перед §11 (и вообще перед QA на свежем конкурсе) имеет смысл подчистить список.

**Полная инструкция:** [DEV_SETUP.md — Remove extra / deleted contests](DEV_SETUP.md#remove-extra--deleted-contests).


| Статус конкурса | Как убрать из списка                                                                                           |
| --------------- | -------------------------------------------------------------------------------------------------------------- |
| **DRAFT**       | Шапка → выбрать конкурс → `/admin/settings/parameters` → «Удалить конкурс» (мгновенно)                         |
| **RUNNING**     | Там же → «Остановить конкурс» → подождать **10 с** (grace, `CONTEST_DELETE_GRACE_SECONDS`) → «Удалить конкурс» |
| **PAUSED**      | «Удалить конкурс» (после grace, если не прошло — подождать)                                                    |
| **FINISHED**    | Удаление из UI недоступно — оставить или полный сброс БД                                                       |


Массового скрипта «удалить все DRAFT» **нет** — перебор в UI или ядерный вариант ниже.

**После soft-delete** (конкурс скрыт, но строка ещё в БД) — вычистить из базы:

```bash
uv run python src/scripts/purge_deleted_contests.py --all-deleted --dry-run
uv run python src/scripts/purge_deleted_contests.py --all-deleted
```

**Ядерный сброс** (один конкурс `id=1`, фикстура dev) — когда мусора слишком много:

```bash
uv run python src/scripts/dev_setup.py
# API/UI не трогать или перезапустить: dev_setup.py --run-only
```

> **Сохранить:** конкурс `id=1` и демо-участников — не делать полный reset, если они нужны для маршрута B (§9). Удаляйте только лишние id ≥ 2.

## 11. Кросс-проверка организатора и участников (end-to-end)

**Цель:** на одном свежем конкурсе проверить, что действия организатора (SUPERVISOR) и то, что видят участники (USER) и гость, согласованы **до** и **после** дедлайна прогнозов.

**Связанные сценарии:** S1.1–S1.12, S2.1–S2.5, S4.1–S4.4, S6.2–S6.3, UC-7–UC-9.

**Время:** ~20 мин подготовка + **ожидание дедлайна** (рекомендуется 7–10 мин) + ~15 мин проверка после.

**Важно:**

- Организатор **не может** вводить прогнозы за участников — только войти под их логином (`USER`) или вызвать API с их токеном.
- У одного логина одна глобальная роль: для игры нужны отдельные аккаунты участников, не `supervisor`. См. [API_GUIDE — Organizer vs participant](API_GUIDE.md#organizer-vs-participant-same-person).
- До дедлайна чужие счета скрыты у `USER` и `SUPERVISOR`; полная матрица до дедлайна — только у `ADMIN`.

### 11.0. Подготовка

1. Запустить стек (если ещё не запущен):

```bash
uv run python src/scripts/dev_setup.py --run-only
# или полный сброс: uv run python src/scripts/dev_setup.py --run
```

1. Открыть UI: `http://127.0.0.1:3000`, API: `http://127.0.0.1:8000`
2. Подготовить **два окна браузера** (или обычное + инкогнито): одно — организатор, другое — участник. Для трёх участников удобно три профиля / инкогнито-сессии.
3. Завести таблицу учёток (заполнять по ходу):


| №   | Имя (для себя) | Логин | Пароль после confirm | Прогноз на тур 1 | Прогноз на тур 2 |
| --- | -------------- | ----- | -------------------- | ---------------- | ---------------- |
| 1   | Тося           |       | ljFMZUK3CD8NIw       | да / нет         | —                |
| 2   | Бося           |       | g3tYrzklXYHEvw       | да / нет         | —                |
| 3   | Котя           |       |                      | да / нет         | —                |


Рекомендуемые параметры конкурса для быстрого прогона: **4 команды**, **2 матча/тур**, **2 тура** (round-robin подставится автоматически).

### 11.1. Организатор: конкурс, команды, участники, старт

**Браузер A** — вход как `supervisor` (пароль из `SEED_SUPERVISOR_PASSWORD`, см. [BOOTSTRAP_USERS.md](BOOTSTRAP_USERS.md)).


| Шаг | Действие               | Маршрут / UI                                       | Ожидание                                                                                                                         |
| --- | ---------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Создать конкурс        | «+ Новый конкурс»                                  | Модалка: название + slug; конкурс в списке, статус `DRAFT`                                                                       |
| 2   | Параметры              | `/admin/settings/parameters`                       | `total_teams = 4`, `matches_per_round = 2`, `total_rounds = 2`; сохранить                                                        |
| 3   | Команды                | `/admin/settings/teams`                            | Добавить **4 команды** (любые имена); в таблице 4 строки                                                                         |
| 4   | Участники              | `/admin/settings/participants`                     | Пригласить **3 участников** (логин + email); в модалке скопировать **временный пароль** и `setup_url` → записать в таблицу §11.0 |
| 5   | Подтвердить участников | CLI (без SMTP)                                     | См. блок ниже                                                                                                                    |
| 6   | Запуск                 | `/admin/settings/parameters` → «Запустить конкурс» | Индикатор готовности зелёный; `RUNNING`, баннер «Конкурс уже запущен»; параметры readonly                                        |


**Подтверждение без почты** (из корня репозитория; `<ID>` — id нового конкурса, виден в шапке или в `GET /contests`):

```bash
uv run python src/scripts/dev_invite_setup.py list-pending
uv run python src/scripts/dev_invite_setup.py confirm-all --contest-id <ID> --password 'TestPass123!'
```

Пароль в `--password` — **новый постоянный пароль** для всех приглашённых (не пароль супервизора). Запишите его в таблицу §11.0.

Перезагрузить `/admin/settings/participants` → у всех троих статус **«Принято»**.

Запомнить `**contest_id`** — он понадобится в URL `/contest/<contest_id>`.

### 11.2. Организатор: туры (один с ближайшим дедлайном)

Остаёмся в **браузере A**, вкладка **Туры** (`/admin/rounds`).

**Тур 1 (основной для проверки дедлайна)**


| Шаг | Действие            | Ожидание                                                                             |
| --- | ------------------- | ------------------------------------------------------------------------------------ |
| 1   | «+ Создать тур»     | Черновик `DRAFT`, 2 матча                                                            |
| 2   | Выбрать пары команд | Без дубликатов команд в туре                                                         |
| 3   | Даты матчей         | Каждый матч **в будущем**; первый матч — не раньше чем через **~2 часа** от «сейчас» |
| 4   | Дедлайн прогнозов   | **Через 7–10 минут** от «сейчас», но **строго раньше** времени первого матча         |
| 5   | «Активировать»      | Подтвердить предупреждение о блокировке; тур → `ACTIVE`; конкурс `is_locked`         |


Запишите **время дедлайна** и **id тура** (из URL или списка).

**Тур 2 (для контраста)**


| Шаг | Действие                  | Ожидание                                                      |
| --- | ------------------------- | ------------------------------------------------------------- |
| 1   | «+ Создать тур»           | Второй черновик `DRAFT`                                       |
| 2   | Заполнить матчи и дедлайн | Дедлайн **через несколько дней**                              |
| 3   | **Не активировать**       | Остаётся `DRAFT`; участники не могут на него ставить прогнозы |

### 11.3. Участники: вход и прогнозы

**Браузер B** (и при необходимости C, D) — только роль **USER**, не организатор.


| Участник  | Шаги                                                                                                                            | Записать в таблицу     |
| --------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| **Алиса** | Вход → `/profile` → «Сделать прогноз» или `/contest/<id>/predict/<round1_id>` → заполнить **все 2 матча** → «Сохранить прогноз» | Прогноз тур 1: **да**  |
| **Боб**   | То же, другие счета (например 1:0 и 2:2)                                                                                        | Прогноз тур 1: **да**  |
| **Вика**  | Войти, открыть конкурс, **не сохранять** прогноз (или выйти, не заполняя)                                                       | Прогноз тур 1: **нет** |


Проверки при вводе:

- Кнопка «Сохранить прогноз» активна только когда заполнены **все** матчи тура.
- После сохранения — «Редактировать» доступно **до дедлайна**.
- На `/profile` ссылка «Сделать прогноз» ведёт на **активный** тур (тур 1), не на черновик тура 2.

Выйти из аккаунта участника перед сверкой (или использовать отдельное окно для гостя).

### 11.4. Сверка **до дедлайна** (пока `now < deadline`)

Проверять **тур 1** (`ACTIVE`). Использовать селектор тура на `/contest/<contest_id>`.

#### Участники и гость — вкладка «Прогнозы»


| Кто смотрит              | Условие                   | Ожидание                                                                                                                     |
| ------------------------ | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **Гость** (не вошёл)     | ACTIVE, дедлайн не прошёл | Заглушка «Будет доступно после дедлайна»; матрицы нет                                                                        |
| **Алиса** (свой прогноз) | вошла                     | Матрица видна; **свои** счета открыты; у Боба — «Прогноз сделан» (`privacy-mask`), счёт не виден; у Вики — пусто / нет маски |
| **Боб**                  | вошёл                     | Свои счета видны; Алиса — маска; Вика — без прогноза                                                                         |
| **Вика**                 | вошла                     | Своя строка без счётов; у Алисы и Боба — маски                                                                               |
| **Любой USER**           | форма прогноза            | `/contest/<id>/predict/<round1_id>` — редактирование **разрешено**, таймер дедлайна тикает                                   |


#### Участники — вкладки «Лидерборд» и «Результаты»


| Вкладка    | Ожидание (тур ещё не `PUBLISHED`)                                                      |
| ---------- | -------------------------------------------------------------------------------------- |
| Лидерборд  | Заглушка / mock или «Будет доступно после проверки организатором» (тур не опубликован) |
| Результаты | Аналогично — нет реальных очков до публикации                                          |


#### Организатор — админка (**браузер A**, всё ещё `supervisor`)


| Маршрут                                        | Ожидание до дедлайна                                                                                             |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `/admin/rounds`, тур 1                         | Статус `ACTIVE`; дедлайн в будущем; состав матчей readonly                                                       |
| `/admin/rounds`, тур 2                         | `DRAFT`; кнопка «Активировать»                                                                                   |
| `/admin/results`                               | Тур 1 **не** в списке для ввода счёта (ещё не `CLOSED`) или поля счёта disabled до дедлайна/начала матча         |
| `/contest/<id>` (если открыть как организатор) | **Те же правила приватности**, что у USER: чужие прогнозы скрыты (организатор не видит «все ставки» до дедлайна) |


#### ADMIN (опционально, для контраста)

Войти как `admin` → `/contest/<id>` → «Прогнозы», тур 1: видны **все** счета всех участников (единственная роль с полной матрицей до дедлайна).

**Зафиксировать время:** сделать скриншоты или отметить в колонке «Статус» чек-листа: `✅ до дедлайна`.

### 11.5. Ожидание дедлайна

1. **Не перезапускать** API (auto-close срабатывает при следующем запросе к конкурсу).
2. Дождаться времени дедлайна + **1–2 минуты** (опрос API или обновление страницы участника).
3. Признак срабатывания:
  - на форме прогноза — «Дедлайн прошёл», сохранение недоступно;
  - тур 1 в админке → эффективно `CLOSED` (или баннер «Дедлайн прогнозов прошёл…»);
  - `GET …/rounds/{id}/predictions` → `deadline_passed: true`.

Можно ускорить отладку запросом к API (подставьте токен участника):

```bash
curl -s "http://127.0.0.1:8000/api/v1/contests/<ID>/rounds/<ROUND1_ID>/predictions" \
  -H "Authorization: Bearer <token>"
```

### 11.6. Сверка **после дедлайна** (`now >= deadline`)

#### Участники и гость — «Прогнозы», тур 1


| Кто                    | Ожидание                                                       |
| ---------------------- | -------------------------------------------------------------- |
| **Гость**              | Полная матрица; видны счета Алисы и Боба; у Вики пусто         |
| **Алиса / Боб / Вика** | Все submitted-прогнозы **открыты**; масок `privacy-mask` нет   |
| **Вика**               | Форма `/predict/<round1_id>` — только просмотр, без сохранения |


Внизу матрицы (если реализовано) — блок «Статистика» П1/Х/П2.

#### Организатор — админка


| Маршрут                          | Ожидание после дедлайна                                                                         |
| -------------------------------- | ----------------------------------------------------------------------------------------------- |
| `/admin/rounds`, тур 1           | Сообщение о закрытии прогнозов; CTA перейти к результатам                                       |
| `/admin/results`                 | Тур 1 в списке (`CLOSED`); после начала матча — ввод счёта, «Рассчитать», «Опубликовать» (S3.x) |
| `/contest/<id>` под `supervisor` | Как у USER: полная матрица прогнозов на закрытом туре                                           |


#### Лидерборд и результаты (ещё без публикации)


| Вкладка                | Ожидание                                                                                                                                       |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Лидерборд / Результаты | До «Опубликовать» на `/admin/results` — по-прежнему **не публичны** (`PUBLISHED` only); заглушка «Будет доступно после проверки организатором» |


Это разделяет **открытие прогнозов после дедлайна** (UC-8/UC-9) и **публикацию очков** (UC-10/UC-12).
