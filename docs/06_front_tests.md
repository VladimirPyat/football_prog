# Стратегия тестирования фронтенда

## Автоматические тесты (обязательно)

### Юнит-тесты (Vitest)
- Файлы: `src/lib/validation/*.test.ts`, `src/lib/privacy/*.test.ts`
- Покрытие: валидация прогнозов, batch rules, privacy logic, 24h rule, error parser
- Запуск: `npm run test:unit`
- Цель: убедиться что бизнес-логика работает

### E2E тесты (Playwright)
- Файлы: `e2e/user_full_flow.spec.ts`, `e2e/prediction_validation.spec.ts`, `e2e/supervisor_create_round.spec.ts`, `e2e/rbac.spec.ts`
- Покрытие: основные user journeys (login → predict → logout, validation, admin flow (supervisor), RBAC)
- Запуск: `npm run test:e2e`
- Цель: убедиться что критичные flows работают

## Ручное тестирование (обязательно)

### Чеклист
визуальное соответствие, UX, мобильная адаптивность, edge cases.
ВАЖНО это тестирует человек, а не агент. Но в конце автоматических тестов, агент напоминает, что разработчик должен сам оценить этот этап

### Что проверять
- Соответствие скриншотам (колонки, цвета, layout)
- Навигация и переходы
- Валидация форм (ошибки под полями)
- Состояния кнопок (disabled/enabled)
- Мобильная версия (горизонтальный скролл, переключатель)

## Критерии готовности
- [ ] Все юнит-тесты проходят
- [ ] Все E2E тесты проходят
- [ ] Ручной чеклист выполнен
- [ ] Визуальное соответствие скриншотам подтверждено
