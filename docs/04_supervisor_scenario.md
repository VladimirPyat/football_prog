# Пользовательские сценарии: Supervisor (Организатор)

## Общие ограничения
- Управление турами, матчами, результатами, рассылками
- Запрет на изменение правил после старта (immutable)
- Правило "заморозки" после дедлайнов
- Доступ через UI/API, без прямого SQL

**Скриншоты**: `supervisor_settings.jpg`, `supervisor_settings2.jpg`, `supervisor_settings3.jpg`

---

## Сценарий 1: Настройка параметров конкурса
- **Маршрут**: `/admin/settings/parameters`
- Все поля `readonly` (конкурс запущен)
- Отображаются: команды (по умолчанию 16), туры (30), матчи/тур (8), формула (12/8/4), бонусы (1-5, 1-5, 5-10, порог 50)

---

## Сценарий 2: Управление участниками
- **Маршрут**: `/admin/settings/participants`
- Таблица: Имя, Email, Статус («Ожидаем» / «Принято»)
- Кнопки «Добавить/Удалить» → disabled после старта
- До старта: ввод email → «Выслать приглашение» → генерация временного пароля

---

## Сценарий 3: Управление командами
- **Маршрут**: `/admin/settings/teams`
- Таблица: Название, Сокращение, Логотип
- Кнопка «Добавить команду» → disabled после старта (исключение: кубки, настраивается)

---

## Сценарий 4: Настройка рассылок
- **Маршрут**: `/admin/newsletters`
- Список: Тип, Текст, Дата, Статус
- Создание: «Разово» / «По расписанию» → текст с `{tournament_name}`, `{round_number}`, `{deadline_date}`
- Шаблоны: «Напоминание о дедлайне» → триггер за 1/2/3 суток

---
**Скриншоты**:  `supervisor_tours.jpg`

## Сценарий 5: Формирование расписания тура
- **Маршрут**: `/admin/rounds`
- Выбор тура (1-30) → «Загрузить по API» или «Добавить матч» вручную
- Валидация: макс. 8 матчей, уникальность команд в туре
- Дедлайн: datetime picker. Проверка `deadline < first_match_date - 24h`
- Активация: модалка «Редактирование запрещено» → статус `DRAFT → ACTIVE`

---

## Сценарий 6: Редактирование активного тура (до дедлайна)
- Разрешено: менять домашнюю/гостевую, дату/время, статус («Состоится»/«Перенесён»/«Отменён»)
- Запрещено: добавлять/удалять матчи, менять дедлайн (<24h)
- Сохранение → предложение повторной рассылки

---

## Сценарий 7: Создание свободного тура (Free Tour)
- Кнопка «Свободный тур» → модалка
- Выбор только `POSTPONED` матчей из разных туров
- Указание новой даты/времени (команды readonly)
- Активация → отдельный тур, матчи удаляются из основного

---

**Скриншоты**:  `supervisor_results.jpg`

## Сценарий 8: Ввод результатов матчей
- **Маршрут**: `/admin/results`
- Выбор завершенного тура → ввод счета (0-20) для каждого матча
- Статус «Завершён» → «Применить результаты»
- После применения: счёт locked, запуск batch-расчёта, обновление лидерборда, статус `CLOSED → CALCULATED → PUBLISHED`

---

## Сценарий 9: Отмена завершённого матча (VOID)
- Кнопка «Отменить» → подтверждение
- Система: статус `FINISHED → VOID`, очки = 0, пересчёт лидерборда (транзакция), audit log
- Нельзя вернуть `FINISHED` (только Support override)

---

## Сценарий 10: Правило 24 часов
- Попытка изменить дедлайн <24h → поле `disabled`, ошибка UI
- API: `400 Bad Request`

---

## API контракты (Supervisor endpoints)
...
POST /api/v1/admin/rounds
Request: { number, deadline, matches: [{team1_id, team2_id, date_time}] }
Rules: max 8, unique teams, 24h check
Response: { round_id, status: 'DRAFT'|'ACTIVE' }

PUT /api/v1/admin/matches/{id}/result
Request: { score1: 0-20, score2: 0-20, status: 'FINISHED' }
Response: { success: true, round_id, calculation_triggered: true }

PATCH /api/v1/admin/matches/{id}/status
Request: { status: 'VOID'|'POSTPONED'|'CANCELED' }
Response: { success: true, recalculation_triggered: true }

POST /api/v1/admin/rounds/free-tour
Request: { matches: [{match_id, new_date_time}], deadline }
Response: { round_id, round_number: 31 }
...
