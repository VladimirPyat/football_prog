# Пользовательские сценарии: User (Участник)

## Общие ограничения
- Валидация на уровне UI (целые числа ≥0)
- Все переходы через кнопки/ссылки
- Не используем моки даже на этапе разработки (к моменту разработки фронта должен быть готов бэк)

**Скриншоты**: `user_leaderboard.jpg`, `user_predict.jpg`, `user_result.jpg`

---

## Сценарий 1: Главная страница (/)
**Роль**: Visitor
1. **Лидерборд**: Таблица с колонками: Место, Фамилия Имя, Дано прогнозов, Точный крупный счет, Точный счет, Разница, Исход, Бонусы 1/2/3, Итого без/с бонусами, Общее число очков.
2. **Навигация**: Под таблицей ссылки «ПРОГНОЗЫ» и «РЕЗУЛЬТАТЫ» → выпадающий список туров (1..N). Текущий тур показывает : «Будет доступно после дедлайна» / «Результаты будут доступны после подведения итогов». Прошедшие туры должны показывать данные
3. **Таблица прогнозов**: 9 колонок. Шапка: «Счет» + прочерки | «Тур 9» + пары команд. Блок результатов: фамилии + предсказанные счета. Блок статистики внизу: кол-во прогнозов на победу/ничью/проигрыш.
4. **Таблица результатов**: Та же шапка, но в первой строке фактические счета. На пересечении фамилий и матчей — очки (0, 4, 8, 12). Справа доп. колонки: бонусы, итоги, верных исходов (0-8).

---

## Сценарий 2: Авторизация и Личный кабинет (/profile)
**Роль**: User
1. **Вход**: Кнопка «Вход» → модалка (Логин, Пароль). Тест: `user / user`. Успех → редирект `/profile`. Авторизованный пользователь видит свой логин вместо кнопки.
2. **Меню /profile**: Контакты (email, VK, проверочный код, галочка уведомлений), Сделать прогноз (/round/{id}/predict), Просмотр результатов, Личная статистика (заглушка), Выйти (→ `/`).
3. **По умолчанию**: Центр страницы показывает форму прогноза (если тур активен и дедлайн не прошел) или результаты тура.

---

## Сценарий 3: Ввод и редактирование прогноза
**Маршрут**: `/round/{id}/predict`
1. **Отображение**: Выпадающий список туров от текущего до последнего (обычно 30). Список матчей: место, время, команды. Два поля ввода: `[Команда A] _ : _ [Команда B]`.
2. **Валидация**: Только целые `0..20`. Частичное сохранение запрещено. Кнопка «Сохранить прогноз» активна только при 100% заполнении.
3. **Дедлайн**: До дедлайна можно редактировать (кнопка «Редактировать» активна). После дедлайна кнопка disabled, поля readonly, API возвращает 403.

---

## Сценарий 4: Приватность прогнозов
- **Pre-Deadline**: User видит свои счета, у других статус «Прогноз сделан». Visitor видит заглушку.
- **Post-Deadline**: Все видят полную таблицу. Статус тура `ACTIVE → CLOSED`. UI блокирует правки.

## E2E тестовые сценарии (Playwright)

// e2e/user_full_flow.spec.ts
1. Visitor → / → видит лидерборд
2. Вход → user/user → успех → /profile
3. «Сделать прогноз» → заполнить 8 матчей → Save → Edit появляется
4. Выход → Visitor

// e2e/prediction_validation.spec.ts
1. 7/8 матчей → кнопка disabled
2. Нечисловой символ → блок
3. 25 → ошибка
4. 8/8 → активна → сохранение

// e2e/deadline_block.spec.ts
1. Сохранение прогноза
2. Support меняет deadline в БД (либо скриптом, либо ставим дедлайн через 3 минуты и ждем)
3. Обновление → кнопка disabled, поля readonly
4. PUT → 403

## API контракты (User endpoints)

`GET /api/v1/rounds/{id}/leaderboard`
Response: { round_id, round_number, leaderboard: [{rank, user_id, user_name, predictions_count, exact_score, exact_diff, exact_outcome, bonus1, bonus2, bonus3, total}] }

`POST /api/v1/rounds/{id}/predictions`
Request: { predictions: [{match_id, score1: 0-20, score2: 0-20}] }
Rules: All matches required. Atomic save.
Response: { success: true, saved_count: 8 }
Errors: 400, 403, 422

`GET /api/v1/rounds/{id}/results`
Response: { round_id, matches: [{id, team1, team2, score1, score2}], results: [{user_id, user_name, points: [{match_id, points}], bonus1, bonus2, bonus3, total, correct_outcomes}] }
